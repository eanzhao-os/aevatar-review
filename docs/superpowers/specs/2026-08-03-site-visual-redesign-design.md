# Aevatar Review 全站视觉重构设计

> 批准日期：2026-08-03
>
> 适用站点：`aevatar-review` 的 MkDocs Material 文档站

## 1. 目标与边界

本次重构保留全部 72 篇实质章节、14 个 block、现有 URL、锚点、事实源结构与上下篇导航，只重构站点外壳。目标是把拥挤的顶部章节栏替换为清晰的左侧导航，并以“清透薄荷”建立一致、明快且适合长文阅读的视觉系统。

不迁移文档引擎，不复制 Material 模板，不引入 JavaScript 或新依赖，也不修改只读事实源 `~/Code/aevatar`。

## 2. 方案选择

采用 Material 原生重构：继续让 `mkdocs.yml` 作为唯一导航事实源，移除 `navigation.tabs` 与全量展开行为，使用 Material 已有的桌面侧边栏、移动端抽屉、搜索、页内目录和分页。

未采用模板覆写，因为复制主题 DOM 会把当前的一次视觉改造变成长期升级负担；未迁移 Astro 或 VitePress，因为现有 Markdown 扩展、搜索、Mermaid 和部署链路已经满足需求，换框架不会改善内容本身。

## 3. 导航与页面骨架

- 桌面端使用“左侧全书导航 + 中间正文 + 右侧页内目录”三栏结构。
- 左侧按 00–13 分组，当前 block 展开、当前章节高亮；不在 CSS 或 HTML 中维护第二份目录。
- 顶栏只承载品牌、搜索、明暗模式和仓库入口，不再承载 15 个顶级入口。
- 正文限制在舒适阅读宽度，宽表格与 Mermaid 在自身容器内横向滚动，不撑宽整页。
- 小屏沿用 Material 原生抽屉与单栏正文，所有导航、搜索和页内目录仍可访问。

## 4. 视觉系统

浅色模式以 `#F7FFFC` 为页面背景、`#E9FBF4` 为侧栏层、`#08745B` 为可读主色、`#0EAF83` 为装饰强调色、`#17352F` 为正文色。深色模式使用深青黑背景和降低亮度的薄荷强调色，维持相同层级而非简单反相。主色在浅色背景上的对比度必须不低于 `4.5:1`；明亮强调色不单独承载文字或键盘焦点状态。

字体继续使用 Noto Sans SC 与 JetBrains Mono。标题提高字重并收紧字距，正文保持较宽行高；卡片、搜索、表格、代码、admonition、分页与 Mermaid 共享轻边框、小圆角和克制阴影。交互状态同时使用颜色、背景或边框表达，并提供可见键盘焦点；短 CSS 过渡在 `prefers-reduced-motion` 下关闭。

## 5. 首页

首页从信息表格改为阅读入口：

1. 首屏说明站点定位、冻结基线与 14/72 规模，并提供“开始阅读”和“查看阅读路线”两个明确入口；
2. 三张路径卡分别服务快速上手、理解架构、实践与查证；
3. 以紧凑统计条和证据状态说明取代大表格，完整目录继续交给侧边栏；
4. 保留 PLAN、README 与外部仓库边界入口。

首页不复制 14 个 block 的完整导航，避免与 `mkdocs.yml` 形成双事实源。

## 6. 回归保护与验收

重写现有 `scripts/check-site-ui.py`，使它验证：

- 配置不再启用顶部 tabs，仍保留唯一 `nav` 树，并加载自定义样式；
- 两套 palette 使用 custom 主题变量；
- CSS 定义清透薄荷 token、侧栏/正文/组件样式、Mermaid 溢出和 reduced-motion 规则；
- 首页包含唯一 H1、主行动入口与三条阅读路径；
- 构建产物存在桌面侧栏、没有顶部 tabs、加载自定义 CSS，且所有页面图标路径有效。

实施遵循测试先行：先修改 UI 契约并观察旧站失败，再完成最小配置、CSS 与首页改动使其通过。最终运行源码 UI 检查、严格 MkDocs 构建、构建产物 UI 检查、Markdown、链接、漂移和 Mermaid 全量门禁，并在桌面与移动视口实际检查首页和章节页。

## 7. 非目标

- 不改章节正文、章节顺序、URL 或事实源引用；
- 不新增 logo 图片、插画、动画库、前端框架或客户端状态；
- 不覆写 Material 模板；
- 不整理工作区中与本任务无关的既有未提交文件。
