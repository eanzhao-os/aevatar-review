# 章节导航双行布局设计

> 批准日期：2026-07-25
>
> 适用站点：`aevatar-review` 的 MkDocs Material 桌面端导航

## 1. 问题与目标

站点当前使用 `navigation.tabs` 展示“首页 + 00–12”共 14 个顶级入口。Material 默认把 tabs 保持在单行可横向滚动容器中，同时隐藏滚动条。顶栏内容总宽度大于站点约 `61rem` 的网格宽度，导致后半章节虽然存在于 DOM 和 `mkdocs.yml`，却在常见桌面视口中位于不可见区域。

本次修复的目标是：

- 在 `1280px` 及以上的桌面视口中，无需横向滚动即可看到全部 14 个顶级入口；
- 保留完整章名、当前章节高亮和现有阅读习惯；
- 保留 Material 在较窄视口下的抽屉导航；
- 继续以 `mkdocs.yml` 的 `nav` 作为唯一导航事实源，不维护第二份章节清单；
- 不修改章节内容、URL、导航层级或只读源码仓库 `~/Code/aevatar`。

## 2. 方案比较与选择

### 方案 A：双行顶部章节栏（采用）

让桌面 tabs 列表允许换行，并让 tabs 容器高度随两行内容展开。完整章名继续显示，新增顶级章节仍由 `mkdocs.yml` 自动渲染。

优点是改动小、信息完整、与现有交互一致；代价是顶部导航会多占一行垂直空间。

### 方案 B：单行编号栏（未采用）

顶栏只显示 `00–12`，完整章名留给侧栏。它最紧凑，但首次访问者需要记忆编号与主题的映射。

### 方案 C：全部章节常驻左栏（未采用）

移除桌面 tabs，在左栏展示全书目录。它的发现性最强，但长目录更拥挤，也会减少正文横向空间。

用户在视觉对比中选择方案 A。

## 3. 布局与响应式行为

实现只增加一份站点样式，并通过 `mkdocs.yml` 的 `extra_css` 加载：

- 桌面端：`.md-tabs__list` 从单行滚动改为 `flex-wrap: wrap`；`.md-tabs__item` 保持 Material 原有链接、高亮和键盘焦点行为；tabs 外层允许内容撑开到两行。
- 较窄视口：沿用 Material 自身的 `max-width: 76.234375em` 断点。此时 `.md-tabs` 本来就会隐藏，用户继续通过抽屉访问完整目录，因此不覆盖该行为。
- 导航内容：不在 CSS、JavaScript 或模板中硬编码章节名称。所有入口仍由 `mkdocs.yml` 生成。

不引入主题 override 或 JavaScript。这个边界可以避免复制 Material 的模板结构，也降低未来主题升级时的维护成本。

## 4. 回归保护

新增一个轻量站点 UI 检查脚本，验证：

1. `mkdocs.yml` 已加载章节导航样式；
2. 样式只在桌面 tabs 可见范围内启用双行布局；
3. 样式包含 `flex-wrap: wrap`，且没有通过隐藏、截断或硬编码章节来“解决”溢出；
4. `mkdocs.yml` 中的全部顶级导航入口仍可由构建产物生成。

实施采用测试先行：先让检查脚本因缺少样式而失败，再加入最小 CSS 和配置使其通过。

## 5. 验收标准

- `1280px`、`1440px` 和更宽桌面视口下，首页与 `00–12` 全部直接可见；
- 顶栏形成最多两行，不出现隐藏横向滚动条才能访问的入口；
- 当前顶级章节的 Material 高亮仍正常；
- 小于 Material 桌面 tabs 断点时，顶部 tabs 隐藏且抽屉导航仍可访问全部章节；
- `mkdocs build --strict --clean` 通过；
- `bash scripts/check-md.sh` 与 `python3 scripts/check-mermaid.py` 的结果不因本次 UI 改动恶化；
- 不修改 `~/Code/aevatar`，不改任何章节正文。

## 6. 非目标

- 不重新设计配色、字体、页头或正文排版；
- 不重组当前 `00–12` 信息架构；
- 不解决章节自身内容、事实源或 Mermaid 的既有问题；
- 不新增下拉菜单、分页菜单或自定义导航数据模型。
